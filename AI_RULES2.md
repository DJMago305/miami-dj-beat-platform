# AI RULES — MIAMI DJ BEAT PLATFORM

You are working on a production-level web platform for DJs, bookings, and services.

This project requires STRICT CONTROL. Any uncontrolled change is considered a FAILURE.

---

## 🔒 CORE PRINCIPLE

DO NOT BREAK EXISTING FUNCTIONALITY.

If something is already working:
→ DO NOT TOUCH IT.

---

## 🎯 SCOPE CONTROL (CRITICAL)

You must ONLY modify what is explicitly requested.

STRICTLY FORBIDDEN:
- Modifying layout structure
- Changing positioning of elements
- Altering CSS globally
- Refactoring existing working code
- Renaming classes or IDs
- Adding wrappers, divs, or containers
- Injecting new UI elements
- Touching unrelated files or sections

If the request is:
→ "Change text"

Then you ONLY change text.

Nothing else.

---

## 🧠 EXECUTION PROTOCOL

Before making ANY change:

1. ANALYZE the request
2. IDENTIFY exact file(s)
3. IDENTIFY exact line(s)
4. EXPLAIN what will be changed

Then:

→ WAIT for user confirmation

DO NOT EXECUTE immediately.

---

## ✂️ SURGICAL EDIT MODE

All changes must be:

- Minimal
- Localized
- Reversible

You must:

- Show BEFORE code
- Show AFTER code
- Specify FILE NAME
- Specify LINE RANGE

NO full rewrites.
NO large patches.

---

## 🎨 UI / LAYOUT PROTECTION (VERY IMPORTANT)

The UI structure is LOCKED.

DO NOT:
- Move tabs
- Resize components
- Change alignment
- Modify spacing
- Add sliders, dropdown replacements, or alternative layouts
- Introduce hidden elements or overlays

If layout changes are required:

→ ASK FIRST

---

## 🧩 TABS / MENU / NAVIGATION RULES

Tabs and navigation are HIGH-RISK areas.

STRICT RULES:
- Do NOT change tab structure
- Do NOT wrap tabs in new containers
- Do NOT add scroll/slider behavior
- Do NOT overlay invisible elements
- Do NOT change click behavior

Only allowed:
→ Text changes inside tabs (if requested)

---

## ⚙️ FUNCTIONALITY PROTECTION

DO NOT:
- Remove event listeners
- Modify JS logic outside scope
- Break interactions between components
- Change data flow

If touching JS:
→ Modify ONLY the required function/line

---

## 🚫 NO AUTO-IMPROVEMENTS

DO NOT:
- "Optimize"
- "Refactor"
- "Clean up"
- "Enhance UX"

Unless explicitly requested.

---

## ❗ ERROR HANDLING

If something is unclear:

→ STOP  
→ ASK QUESTIONS

Do NOT guess.

---

## 🔍 VERIFICATION RULE

After applying changes:

You must state:

- What was changed
- What was NOT changed
- Why no other areas were touched

---

## 🧨 RED FLAGS (STOP IMMEDIATELY IF:)

- You need to modify more than one section
- You are about to change layout
- You are unsure of side effects
- You are touching shared/global styles

→ STOP AND ASK

---

## 🏁 GOAL

Maintain FULL STABILITY of the platform while applying ONLY the requested change.

No regressions.
No side effects.
No surprises.

---

## 🧾 PRIORITY ORDER

1. Preserve existing functionality
2. Respect scope
3. Apply minimal change
4. Maintain UI integrity
5. Then complete the task

---

END OF RULES
